# Results delta: earlier draft -> current

**The paper is already up to date.** `access.tex` was checked cell by cell against
`reference/analysis/`: `tab:results_main` differs in **0 of 231 cells**, and
`tab:top_ssl_lineage`'s Mean EERs match to printed precision. `tab:acoustic_degradation`
is a composition table and carries no EERs; the degradation and TTS results are figures.

So nothing here is a change still to be made. This is the record of what moved when the
v3 score tree replaced the old one -- for the revision history, and for answering a
reviewer who asks why a number differs from an earlier version.

`results_delta.csv` beside this file is the same data, one row per cell.

## Why, per column

**ASV19 LA** -- **Not explained by coverage.** Same finding as ITW: 0/19 reproduce on identical trials.

**ASV21 LA** -- Stable. 12/19 moved, median 0.001 pp.

**ASV21 DF** -- **Coverage.** The published column was 152,955 rows of a 611,829-row protocol.

**ASV5 Eval** -- Largely stable; 15/19 moved, median 0.004 pp.

**ITW** -- **Not explained by coverage.** P12 found 0/19 cells reproduce between the trees on identical trials with zero label disagreement. The old column's scores have no regenerable source.

**DFEval24** -- **Different measurement.** 1,976 trials (one 4 s window per recording) -> 56,481 (every window). Per-segment trials weight long recordings far more heavily.

**FF** -- **Coverage**, plus the bonafide directory naming (`-` vs `Bonafide`) that made the two trees look disjoint until ids were reconciled.

**ASVLD** -- **Coverage.** Now one file from the combined protocol (2,065,873 rows) instead of two pooled by hand, one of which was a separate Recompression re-run.

**MLAAD** -- **Corpus replaced.** The old column was 307,998 rows of `linear_head_Multilingual`, and for four models 98.085% of its spoof rows were NaN -- that figure WAS the printed EER. Now MLAAD v10 (456,000 spoof) pooled with M-AILABS (584,006 bonafide) = 1,040,006 rows.

**SpoofCeleb** -- Largely stable; median 0.011 pp. Three cells are the flat-DET `SENSITIVE` case -- rank correlation 1.000000 with the EER still moving (tera by 4.15 pp).

## The two that are not coverage

ASV19 LA and ITW are the ones worth being able to answer on. Every other moved column
has a documented cause -- a replaced corpus, a widened protocol, a changed measurement.
Those two moved on **identical trial sets with zero label disagreement**, which means the
old scores cannot be regenerated by any pipeline in this repo. Recorded as P12 in
`PLANNED_CHANGES.md`; the current values are the reproducible ones.

The two non-SSL rows are a separate case (P13): LFCC-GMM reproduces bit-identically
because it involves no gradient-based training, while AASIST does not, because it is
trained from random initialisation and the published row is a property of a checkpoint.
